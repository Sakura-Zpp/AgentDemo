# 故障恢复说明

## 恢复目标

Demo 基线建议 RPO 24 小时、RTO 60 分钟。正式环境应根据数据等级重新批准目标并做演练记录。

## 备份范围

- PostgreSQL：Checkpoint 数据库的定期快照或逻辑备份。
- 单实例本地数据：`.agent_data/checkpoints.sqlite3` 与 `.agent_data/long_term_memory.sqlite3`，备份前停止写入或使用 SQLite 在线备份接口。
- 知识索引：`chroma_db/`、`bm25_index.json`、`.index_revision` 和 `sha256.text` 必须同批备份。历史 `bm25_index.pkl` 不应再反序列化。
- 配置与提示词：从版本库恢复；密钥从密钥管理系统恢复，不进入备份包。

## 恢复步骤

1. 隔离故障实例并保存日志，不在原数据上反复写入。
2. 在临时环境恢复数据库和同版本知识索引。
3. 执行健康检查、静态门禁和非 E2E 测试。
4. 用测试身份验证新会话、会话恢复、用户隔离、显式记忆删除和 RAG 查询。
5. 切换流量，观察错误率与 P95 延迟；异常时回切旧实例。

## 场景处置

- MCP 服务故障：停用对应服务；知识与报告 Agent 应继续工作。
- Reranker 故障：系统自动降级为混合召回顺序，检查告警后恢复服务。
- Chroma/BM25 不一致：回滚整套索引，或清空摘要清单后从可信原文完整重建。
- Checkpoint 损坏：恢复数据库备份；无法恢复的 thread 应明确告知用户开启新会话。
- 密钥泄露：立即在供应商侧吊销并轮换，更新密钥管理系统，检查日志和调用审计。

## 演练验收

每季度至少演练一次；记录备份时间、实际 RPO/RTO、校验结果、失败点、负责人和后续整改项。
